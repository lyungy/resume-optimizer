# 简历驱动的智能岗位匹配方案

> 版本：v1.0 | 日期：2026-05-24

---

## 一、策略转变

### 1.1 当前策略（岗位驱动）

```
泛搜关键词 → 批量采集 → 逐个分析大龄友好度 → 筛选
```

**问题**：
- 搜索关键词靠人猜，可能遗漏合适岗位
- 只筛选"大龄友好"，不评估和简历的匹配度
- 采集了大量无关岗位，浪费时间和反爬配额

### 1.2 新策略（简历驱动）

```
深度解析简历 → 拆解多维度数据 → 生成精准搜索策略 → 采集 → 多维匹配打分 → 排序推荐
```

**优势**：
- 搜索词从简历自动推导，不靠人猜
- 匹配度多维评估，不止看年龄
- 精准搜索减少无效采集

## 二、简历维度拆解

### 2.1 拆解维度

从简历中提取以下维度数据：

```
简历
├── 📌 核心技能（hard_skills）
│   ├── 编程语言：Java, Python, Go, ...
│   ├── 框架：Spring Boot, FastAPI, ...
│   ├── 中间件：Kafka, Redis, ES, ...
│   ├── 架构：微服务, 分布式, DDD, ...
│   └── 工具：K8s, Docker, CI/CD, ...
│
├── 📌 软技能（soft_skills）
│   ├── 管理：团队管理, 项目管理, 跨部门协作
│   ├── 技术：架构设计, 技术选型, 性能优化
│   └── 业务：需求分析, 产品思维, 业务理解
│
├── 📌 经验画像（experience_profile）
│   ├── 工作年限：15 年
│   ├── 最高职位：技术总监 / 架构师
│   ├── 管理规模：20 人团队
│   ├── 行业经验：互联网, 电商, 金融, ...
│   └── 公司规模：大厂 / 中型 / 创业公司
│
├── 📌 教育背景（education）
│   ├── 学历：本科 / 硕士
│   ├── 专业：计算机科学
│   └── 学校：985 / 211 / 普通
│
├── 📌 求职偏好（job_preference）
│   ├── 期望职位：架构师 / 技术总监 / CTO
│   ├── 期望薪资：40-60K
│   ├── 期望城市：上海
│   ├── 接受远程：是 / 否
│   └── 行业偏好：互联网 / 金融科技 / AI
│
└── 📌 项目亮点（project_highlights）
    ├── 核心项目：XX 系统架构设计（日活百万）
    ├── 技术亮点：高并发, 微服务改造, 性能优化
    └── 业务成果：成本降低 30%, 效率提升 50%
```

### 2.2 数据来源

| 维度 | 来现 | 提取方式 |
|------|------|----------|
| 核心技能 | `resume.skills`（LLM 解析） | ✅ 已有 |
| 工作年限 | `resume.experience_years` | ✅ 已有 |
| 教育背景 | `resume.education` | ✅ 已有 |
| 工作经历 | `resume.work_experience` | ✅ 已有 |
| 项目经历 | `resume.projects` | ✅ 已有 |
| **软技能** | ❌ 无 | 🆕 需新增 |
| **经验画像** | ❌ 无（需从 work_experience 推导） | 🆕 需新增 |
| **求职偏好** | ❌ 无 | 🆕 需新增（用户输入） |
| **搜索关键词** | ❌ 无 | 🆕 需从简历自动推导 |

**关键词推导逻辑**：

```

  + 从 job_preference 获取用户期望职位
  → 合并去重 → 按优先级排序
```

### 3.4 Phase 4: 多维匹配打分（核心变更）

**当前打分**：只看"大龄友好度"（0-100 分）

**新打分**：多维度加权匹配

```
总分 = 技能匹配 × 35%
     + 经验匹配 × 20%
     + 薪资匹配 × 15%
     + 职级匹配 × 15%
     + 年龄友好 × 10%
     + 行业匹配 × 5%
```

#### 3.4.1 技能匹配（35 分）

```
skill_match = JD要求的技能 ∩ 我的技能
匹配率 = 命中数 / JD要求总数

匹配率 ≥ 80%  → 35 分
匹配率 ≥ 60%  → 28 分
匹配率 ≥ 40%  → 20 分
匹配率 ≥ 20%  → 12 分
匹配率 < 20%  → 5 分
```

#### 3.4.2 经验匹配（20 分）

```
JD要求 5-10年，我有 15年
  → 15 > 10，超出上限但可接受 → 16 分

JD要求 3-5年，我有 15年
  → 15 >> 5，严重超出 → 8 分（可能被嫌"太资深"）

JD要求 10年以上，我有 15年
  → 完美匹配 → 20 分

JD要求 1-3年，我有 15年
  → 不匹配 → 0 分
```

#### 3.4.3 薪资匹配（15 分）

```
我的期望 40-60K

JD 30-50K  → 上限低于期望下限 → 6 分
JD 40-60K  → 完美匹配 → 15 分
JD 50-80K  → 高于期望 → 12 分（可能要求更高）
JD 15-25K  → 远低于期望 → 0 分
```

#### 3.4.4 职级匹配（15 分）

```
我的历史职位: [技术总监, 架构师, 高级开发]

JD "技术总监"  → 完美匹配 → 15 分
JD "架构师"    → 匹配 → 13 分
JD "高级开发"  → 低于我的级别 → 8 分
JD "CTO"       → 高于我的级别 → 10 分
JD "初级开发"  → 不匹配 → 0 分
```

#### 3.4.5 年龄友好（10 分）

```
复用现有逻辑，但权重从 40 降到 10
（年龄仍然是因素，但不再是唯一决定因素）
```

#### 3.4.6 行业匹配（5 分）

```
我的行业经验: [互联网, 电商, 金融科技]

JD "互联网"    → 匹配 → 5 分
JD "金融科技"  → 匹配 → 5 分
JD "制造业"    → 不匹配 → 2 分
JD "医疗"      → 不匹配 → 2 分
```

## 五、与现有系统的关系

### 5.1 复用的模块

| 模块 | 复用方式 |
|------|----------|
| `resume_service.parse_with_llm` | 复用 LLM 解析简历，扩展输出维度 |
| `jd_service.parse` | 复用 LLM 解析 JD，提取硬性/软性技能 |
| `collector.analyzer` | 保留大龄友好度分析，作为匹配维度之一 |
| `collector.BossPlatform` | 保留搜索采集能力，搜索词来源变更 |

### 5.2 新增/改造的模块

| 模块 | 说明 |
|------|------|
| `collector/matcher.py` | 🆕 多维匹配引擎（简历 vs JD） |
| `collector/profile.py` | 🆕 求职画像生成器（从简历推导搜索策略） |
| `collector/analyzer.py` | 🔧 保留现有，降权年龄维度 |
| `collector/__main__.py` | 🔧 新增 `match` 子命令 |
| `backend/services/resume_service.py` | 🔧 扩展 LLM 解析输出（增加软技能、经验画像） |

## 六、CLI 使用方式

```bash
# 1. 解析简历生成求职画像
python -m collector profile --resume /path/to/resume.docx

# 2. 基于画像自动搜索 + 匹配
python -m collector match --resume-id <uuid>
# 或
python -m collector match --profile /path/to/profile.json

# 3. 用已有搜索结果匹配（不重新搜索）
python -m collector match --resume-id <uuid> --from-file data/latest_search.json

# 4. 指定搜索条件覆盖画像
python -m collector match --resume-id <uuid> -k "架构师" -c 杭州
```
